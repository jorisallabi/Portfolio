How I work on a lab project

I start by defining what should work and how I will verify the result. Then I build progressively, keep configuration copies and test failure scenarios as well.

When something fails, I record the symptom before looking for a cause. I check logs, routes, interface states and dependencies. I change one thing at a time so I can identify what actually fixed the issue.

Project status definitions

  • Delivered: the described scope has been implemented and the stated validations are documented. This does not automatically mean production deployment.
  • Functional — follow-up pending: the main service works in the tested conditions, but one or more validations or improvements remain open.
  • In progress: implementation has started; some scope items, tests or fixes remain.
  • Planned: the need and scope are defined, but implementation has not started.

What I record

  • Actual configuration and software versions.
  • Commands and checks needed to reproduce a test.
  • Observed outcomes, including interruptions and failures.
  • Known limitations and tests not yet performed.

I do not present a learning objective as a completed implementation. If a test is missing, I say so.
