ATLAS: a self-hosted personal assistant

At a glance

ATLAS is a personal assistant accessed through Telegram. It runs locally with n8n and routes requests to dedicated modules.

Automation
Self-hosted n8n
Local model
Ollama · qwen3.5:9b
Data layer
PostgreSQL / Supabase
Interfaces
Telegram · Trello · Google Calendar

Architecture

Telegram sends requests to the ATLAS router through a webhook. The router applies access checks, duplicate protection and request routing. Local model interpretation is limited to structured intent extraction and constrained project planning; it does not write to the database directly.

Modules

  • ATLAS: Telegram entry point, security checks, command routing and planning.
  • JARVIS: deterministic task, event, project and reminder management.
  • JERICHO: multi-source job-offer collection, scoring and human validation.
  • Trello synchronization: bidirectional synchronization between the database and Trello cards.

Execution controls

Business rules and database functions validate data and execution. Project trees are created transactionally, and unique request identifiers help prevent duplicate actions.
